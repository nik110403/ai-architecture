# Coverage

| Module | Use it when | Practical first step |
|---|---|---|
| planning | a request needs a bounded outcome | write outcome, scope, acceptance criteria, and Next |
| agents | work is handed to a worker | give a bounded brief and independently inspect the return |
| context | a repository is too large to preload | list named paths and read only evidence needed now |
| continuity | work must survive a fresh process | checkpoint state, evidence, and one exact Next |
| review | a change needs an independent check | compare artifact against explicit acceptance criteria |
| evaluation | alternatives need a decision | score named candidates with a declared rubric |
| workspace | several projects or notes need routing | maintain a small index of current locations and status |
| design | implementation changes a user experience | write a product brief before building and a critique after |
| research | claims depend on sources | record source, quotation, claim, and uncertainty |
| safety | an action may be consequential | name capabilities and set a freeze before acting |
| maintenance | a system may drift over time | keep a registry and schedule a manual inspection |

Each module is optional guidance. It does not configure an AI product or change its permissions.
