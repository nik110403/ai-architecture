# Contributing

Keep additions project-local, portable, and explicit about what they do not enforce. New skills need frontmatter, triggers, objective, steps, output/done check, failure handling, and a worked example; include any needed asset in the skill directory. Keep tooling stdlib-only unless a dependency is justified and documented.

Run the offline checks in INSTALL before proposing a change. Do not add private paths, personal data, model pins, global settings changes, or copied third-party assets.
